# repi — 英文磨耳朵应用设计

日期：2026-11-02

## 目标

用本地 TTS 把英文课程资料朗读出来，并一直循环播放，直到用户听熟、理解含义。应用常驻后台挂着听，要求启动快、占用低。

## 技术选型

- 框架：[MyGo](https://github.com/egoist/mygo)（Go，纯 Go、无 cgo），使用原生 UI（`ui` 包），不用 webview。
- TTS：本机已装的 `/usr/bin/piper-tts`（注意 `/usr/bin/piper` 是罗技鼠标工具，不是 TTS），音色取自 `/usr/share/piper-voices/`（en_US、en_GB）。
- 播放：MyGo 的 `audio` 包（WAV 解码 + Linux 输出），不依赖外部播放器。

## 核心方案：按句预生成 + 磁盘缓存

文章切成句子，每句用 `piper-tts` 生成一个 wav，缓存后按句顺序播放。

放弃的方案：整篇合成一个长 wav（逐句跳转要自己对齐时间戳）；边播边合成（每轮循环重复耗 CPU）。

## 结构

```
repi/
  main.go
  internal/
    text/    切句：按 . ? ! 和换行切，处理 Mr./Dr./e.g./小数/引号
    tts/     调 piper-tts 生成 wav；缓存键 = hash(音色 + 语速 + 句子文本)
    player/  播放状态机：整篇循环、逐句重复 N 次、暂停、上一句/下一句、跳到指定句
    store/   资料库，JSON 存于 ~/.local/share/repi/
    ui/      MyGo 原生界面
```

各包职责单一。`text` 与 `player` 不依赖窗口，可独立测试；`player` 通过接口依赖音频输出和 TTS，便于用假实现测试。

## 功能

- 资料：粘贴文本、打开 .txt/.md，存为“资料”，列表管理多篇；记住每篇的播放位置与设置。
- 播放模式（一键切换）：
  - 整篇循环（默认）：从头到尾一遍遍循环。
  - 逐句重复：每句重复 N 次再下一句，读完整篇回到开头。
- 控制：播放/暂停、上一句/下一句、语速、音色、“隐藏文字”开关（纯听）。
- 显示：英文逐句排列，当前句高亮，点任意句从该句开始播。不做翻译。
- 合成未完成时，已合成的句子先播，未完成处显示进度。

## 界面布局

左侧资料列表（新建 / 粘贴 / 打开文件）；右侧文章按句排列；底部控制条。

## 数据流

粘贴文本 → 切句 → 后台 goroutine 依次调用 `piper-tts` 输出 wav 并缓存 → 播放器读取已就绪的句子并高亮 → 循环至用户停止。退出时保存每篇的位置与设置。

## 错误处理

- 启动时检查 `piper-tts` 与音色是否存在，缺失则在界面提示，不崩溃。
- 某句合成失败：标红并跳过，继续播放其余句子。
- 音频设备异常：提示并保持暂停，不自动无限重试。

## 测试

- 单元测试：切句规则、播放状态机（循环、重复 N 次、跳句、边界）、缓存键。
- 集成测试：用假 TTS 与假音频输出跑完整播放流程。
- 真机手动验证：能出声、能循环、能长时间运行。

## 不做（YAGNI）

翻译、词典、云端 TTS、剪贴板监听、多平台打包。
